---
name: Bootstrap self-model boundary
description: Bootstrap Awareness uses the executive objective ledger for durable intent and answers six owner questions from one evidence-backed read-only projection.
---

The Bootstrap Awareness projection must remain read-only: it composes existing manifest, readiness, delivery, setup, bridge, task, and rehearsal evidence without creating history or a parallel self-ledger. Its visible K6 objective is initialized idempotently outside the read path in the existing executive-objective system, then referenced by record ID and evidence.

**Why:** A self-model that writes while being read can create false progress, duplicate history, or make a readiness check appear healthier than its sources. A constant-only objective also loses continuity across restarts.

**How to apply:** Preserve the six answer IDs—blockers, broken-systems, next-work, replit-changes, readiness-improvement, subsystem-health—and keep each answer labeled with status, freshness, and source evidence. Missing or stale signals must remain visible as unverified/stale rather than becoming a pass.

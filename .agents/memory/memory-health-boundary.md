---
name: Memory Health boundary
description: Memory Health distinguishes canonical Brain failure from rebuildable retrieval, projection, and cache degradation.
---

Canonical database and Event Log defects fail closed; stale semantic indexes, projections, Working Memory, and caches remain rebuildable warnings and never substitute for canonical evidence. Portable backup health requires an actual payload checksum and isolated restore proof, while provider credentials remain excluded.

**Why:** A machine-loss or retrieval incident must not turn missing derived state into invented certainty, and a manifest that merely contains a checksum field is not integrity evidence.

**How to apply:** Keep owner-facing health checks explicit about PASS/WARN/FAIL, preserve evidence references and recovery steps, version cache keys when evidence shape changes, and require a new empty installation for restore.
